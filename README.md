# Zahiri

**Verified Information, Empowered Minds** — Team I-SET

A fact-checking platform for Nigeria and beyond: an AI + human verification
engine reachable from inside the app, from WhatsApp, and from a newsroom API,
wrapped in a game and a community hub that keep people using it.

```
zahiri/
├── server/          Express + TypeScript API  →  Render
├── mobile/          Expo (React Native)       →  Android APK
├── render.yaml      Render Blueprint
└── README.md
```

---

## What is built

Everything in the feature architecture **except the USSD / SMS fact-check line**,
which was explicitly out of scope for this build.

### Entry points — how a claim reaches Zahiri

| Feature | Where |
|---|---|
| AI fact-checking chatbot | `POST /api/chat`, `POST /api/chat/stream` (SSE) |
| Verify a claim or link | `POST /api/verify/claim` |
| Deepfake & synthetic media detector | `POST /api/verify/media` |
| WhatsApp-native companion | `POST /api/plugins/whatsapp/webhook` |
| Facebook / LinkedIn share-to-Zahiri | `POST /api/plugins/share` |
| Community Verification Hub | `POST /api/hub/posts` |

### Verification engine — what actually decides

| Component | Notes |
|---|---|
| Claim / link analysis | NVIDIA NIM primary, OpenRouter fallback |
| Deepfake detection | Vision model on images; provenance + description for video/audio |
| Provenance & Content Credentials | C2PA / JUMBF / XMP marker detection, generator-string sniffing |
| Source reputation & content-farm score | Running accuracy per domain, smoothed; watchlist |
| Human fact-checker queue | Anything low-confidence, election, health, or naming a person |
| Election & crisis rapid response | `GET /api/alerts/crisis`, ranked by circulation |

### Reinforcement & reach

Truth Hunters game (server-scored, seasonal leaderboard) · Daily personalised
alerts · Points system with an append-only ledger · School sensitisation
campaigns and training modules · Radio partner schedule · Accessibility
preferences · Newsroom & NGO B2B API with hashed keys and monthly quotas.

> **No reward catalogue ships by default.** The redemption machinery exists
> (`/api/rewards/*`, the ledger, admin-created rewards), but nothing is seeded:
> an app about verified information should not promise data bundles or cash it
> cannot deliver. Points drive the leaderboard. Add rewards through
> `POST /api/rewards/catalogue` once a real fulfilment process exists.

### Not built

**USSD / SMS fact-check line** — excluded by request. The engine is already
channel-agnostic (`entryPoint` on every verification), so adding it later means
writing one gateway adapter, not touching the engine.

## Running it locally

### 1. API

```bash
cd server
npm install
cp .env.example .env        # fill in MONGODB_URI, NVIDIA_API_KEY, OPENROUTER_API_KEY, JWT_SECRET
npm run seed                # game rounds, modules, radio partners, sources, alerts
npm run dev                 # http://localhost:8080
```

Useful scripts:

```bash
npm run dbcheck             # full MongoDB Atlas health + integrity report
npm run grant -- admin you@example.com    # grant a privileged role
npm run build && npm start  # production build
```

> **If `npm run seed` fails with `querySrv ECONNREFUSED`** your system resolver
> is refusing SRV lookups, which `mongodb+srv://` needs. Set
> `DNS_SERVERS=8.8.8.8,1.1.1.1` in `.env`. Render's resolver is fine, so leave
> this empty in production.

### 2. Mobile

```bash
cd mobile
npm install
# .env → EXPO_PUBLIC_API_URL=https://your-service.onrender.com
npm start                   # Expo dev server
```

With no `EXPO_PUBLIC_API_URL` set, the app falls back to `http://<metro-host>:8080`,
so a debug build on a physical device reaches your dev machine automatically.

## Deploying the API to Render

1. Push this repository to GitHub.
2. Render → **New → Blueprint** → select the repo. `render.yaml` is detected.
3. Render prompts for the secrets marked `sync: false`:
   - `MONGODB_URI`
   - `NVIDIA_API_KEY`
   - `OPENROUTER_API_KEY`
   - `WHATSAPP_*` (optional, leave blank until WhatsApp is set up)

   `JWT_SECRET` and `WHATSAPP_VERIFY_TOKEN` are generated by Render.
4. In **MongoDB Atlas → Network Access**, allow Render's egress. `0.0.0.0/0` works
   but is broad; pin Render's static outbound IPs if you upgrade to a paid plan.
5. Deploy. Health check is `GET /health`.

### Cold starts on the free plan

An idle free instance is spun down, and the next request waits 30–60 seconds for
it to boot. The app handles this: it pings `/health` on launch so the wake
overlaps with the first screen, retries 502/503/504 with backoff, and shows a
"Waking Zahiri up" banner rather than a network error. Upgrading to Starter
removes the delay.

## Building the Android APK

```bash
cd mobile
npx expo prebuild --platform android --clean
cd android
./gradlew assembleRelease
# → android/app/build/outputs/apk/release/app-release.apk
```

Requires JDK 17 and the Android SDK (platform 36, build-tools 36.x).

**Signing.** `credentials/` holds a 4096-bit RSA keystore valid to 2054, and is
git-ignored. `plugins/withReleaseSigning.js` copies it in and rewrites
`build.gradle` on every prebuild, so the signature stays stable across rebuilds.
**Back that directory up** — losing it means installed apps can never be
upgraded, only uninstalled and reinstalled.

## Security

| Layer | Control |
|---|---|
| Passwords | bcrypt cost 12; 12-char minimum with mixed case and a digit; common-password denylist |
| Sessions | JWT pinned to HS256 with issuer + audience; algorithm confusion and `alg:none` rejected |
| Brute force | Per email+IP lockout after 5 failures in 15 min; identical response for unknown vs. wrong password, so accounts cannot be enumerated |
| Privilege | `factchecker` and `admin` are not self-assignable at sign-up; granted only via `npm run grant` |
| NoSQL injection | `$`-prefixed and dotted keys stripped from every body and query |
| Parameter pollution | Repeated query params collapsed before validation |
| Uploads | Magic-byte validation against the declared MIME type; executables, archives, and scripts rejected outright; filenames stripped of paths and control characters; 20 MB cap |
| Prompt injection | Untrusted content fenced with a per-request nonce, chat-template control tokens stripped, the system prompt told to treat fenced text as material to judge; attempts logged |
| SSRF | Outbound URLs must be HTTPS and public; loopback, RFC1918, CGNAT, and cloud-metadata addresses blocked; WhatsApp media restricted to Meta CDN hosts |
| Webhooks | `X-Hub-Signature-256` HMAC verified against the raw body; fails closed in production |
| API keys | `zah_<prefix>_<secret>`; only a bcrypt hash stored, shown once; constant-time comparison with a dummy hash so timing does not leak prefix existence |
| Transport | HSTS preload in production; strict CSP; `nosniff`; no-referrer; CORS allowlist enforced in production |
| Android | Cleartext HTTP refused; only system CAs trusted, so a user-installed CA cannot MITM; auto-backup disabled |
| Token storage | Device keystore via `expo-secure-store`, never AsyncStorage |
| Audit | Security events emitted as structured JSON for a log drain to alert on |

Rate limits: 120 req/min globally, 15/min on verification, 20 per 15 min on auth.

## AI providers

Both are OpenAI-compatible, so one client drives both, with automatic failover
when the primary is rate-limited or returns 5xx.

| | Model |
|---|---|
| NVIDIA text | `nvidia/nemotron-3.5-lightning-30b-a3b` |
| NVIDIA vision (images) | `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning` |
| OpenRouter text | `openrouter/free` |
| OpenRouter vision | `google/gemma-4-31b-it:free` |

Nemotron models are reasoning models and leak their chain of thought into the
response body unless it is switched off, which destroys structured verdicts —
so the client sends `chat_template_kwargs: { thinking: false }` to NVIDIA and
strips any `<think>` block that still gets through.

A client-side sliding-window guard keeps NVIDIA under 40 requests/minute, so the
free tier is respected before a request is ever sent.

Only images use a vision model; video and audio are judged on provenance plus
the user's description, and the result says plainly that acoustic or frame-level
analysis was not performed.
